Локальный запуск тестов
Начиная с этого спринта, вы разработаете несколько микросервисов, которые вместе образуют систему сбора и анализа телеметрии с умных устройств.
При выполнении финальных заданий вы можете проверять работу своих сервисов локально — прямо на своём компьютере. Для этого мы предлагаем использовать специальный компонент Hub Router, он отправляет тестовые данные вашим сервисам, отслеживает их реакцию и выводит отчёт о прохождении тестов.
Hub Router — это вспомогательный тестовый компонент, который:
генерирует события от «умных устройств» (датчиков);
передаёт их в ваш сервис Collector по HTTP или gRPC;
следит, чтобы данные корректно попадали в Kafka;
при наличии других сервисов (например, Aggregator или Analyzer) проверяет, как они обрабатывают эти данные дальше;
формирует подробный отчёт о ходе теста и его результатах.
Hub Router — это тот же компонент, который используется в автоматическом пайплайне GitHub Actions. С его помощью вы можете протестировать проект локально, не дожидаясь запуска CI-проверок.
Как Hub Router тестирует проект
По мере того, как вы реализуете новые части проекта, Hub Router будет проверять взаимодействие всех сервисов доступных на каждом из этапов.
Этап разработки	Что тестируется
Спринт 19 — Collector (HTTP)	Проверка того, что сервис корректно принимает данные от Hub Router по протоколу HTTP и записывает их в Kafka.
Спринт 20 — Collector (gRPC)	Проверка того, что сервис корректно принимает данные от Hub Router по протоколу gRPC и записывает их в Kafka.
Спринт 20 — Aggregator	Проверка связки Collector + Aggregator: данные не только сохраняются, но и агрегируются
Спринт 20 — Analyzer	Проверка цепочки Collector → Aggregator → Analyzer на корректность анализа и реакцию на сценарии
Таким образом, на каждом этапе Hub Router подключается к уже готовым сервисам и проверяет их совместную работу.
Как запустить Hub Router
Перед запуском убедитесь, что:
Установлена JDK 21 или новее.
Ваш проект собран и запущен.
В папке проекта есть папка hub-router, в которой лежат скрипты запуска и файл hub-router.jar:
hub-router/run-tests.bat — для Windows;
hub-router/run-tests.sh — для Linux/macOS.
hub-router/scripts/hub-router.jar
Hub Router можно запустить вручную через консоль, используя JAR-файл. Однако проще воспользоваться готовыми скриптами, которые уже настроены под каждый этап проекта. Например, главный скрипт run-tests автоматически определяет текущую git-ветку и запускает соответствующий ей тестовый сценарий.
Если название ветки не соответствует ни одному из этапов, нужный скрипт можно выбрать вручную в папке scripts — в подкаталогах windows или macos_linux в зависимости от вашей операционной системы.
Этап	Скрипт	Что проверяет
Collector	- 1-collector-json-tests
- 2-collector-grpc-tests	Приём данных от Hub Router по HTTP (в этом спринте) или по gRPC (в следующем и последующих спринтах), а также запись данных в Kafka
Aggregator	3-aggregator-tests	Совместную работу сервисов Collector и Aggregator
Analyzer	4-analyzer-tests	Полный цикл взаимодействия сервисов: Collector → Aggregator → Analyzer
Все скрипты используют одинаковые базовые настройки: 
тестовый режим в зависимости от этапа;
потоковое логирование отключено (логи не засоряют консоль);
финальный отчёт выводится в консоль после завершения теста;
уровень логов TRACE включён — это даёт подробные сообщения.

Полный запуск и настройки
Hub Router можно запустить вручную, указав нужные аргументы прямо в консоли. Это полезно, если вы хотите изменить поведение тестов, порт или уровень логирования.
Самая простая команда — это вывод краткой информации о проекте:

java -jar hub-router.jar info 
Если вы хотите управлять параметрами вручную, используйте следующую команду:

java -jar hub-router.jar [опции] 
Основные параметры
Параметр	Назначение	Значение по умолчанию
--hub-router.execution.mode	Режим тестирования (COLLECTION, AGGREGATION, ANALYZE)	COLLECTION
--hub-router.execution.collector.mode	Протокол взаимодействия c коллектором (http или grpc)	grpc
--hub-router.execution.collector.port.http	Порт HTTP-сервера коллектора	8080
--hub-router.execution.collector.port.grpc	Порт GRPC-сервера коллектора	59091
--hub-router.execution.output.console	Включить/выключить вывод финального отчёта в консоль	true
--hub-router.execution.output.file	Включить/выключить вывод финального отчёта в файл	true
--hub-router.execution.output.file-path	Путь, куда сохранять файл отчёта	./execution-report.txt
--hub-router.execution.output.trace-enabled	Включить/выключить вывод подробных сообщений	true
--hub-router.execution.output.info-enabled	Включить/выключить вывод информационных сообщений	true
--hub-router.execution.immediate-logging.enabled	Включить/выключить потоковые логи во время выполнения	false
Если вы хотите видеть только ошибки, отключите оба параметра:

--hub-router.execution.output.info-enabled=false
--hub-router.execution.output.trace-enabled=false 
Итого
Hub Router позволяет запускать локальные тесты на тех же сценариях, что и GitHub Actions.
Скрипты автоматически выбирают нужный режим тестирования в зависимости от ветки.
При необходимости можно запустить Hub Router вручную, добавив параметры командной строки.
После завершения теста в консоль выводится детальный отчёт о его результатах.
