Проект интернет-магазина Smart Home Technologies
Компания Smart Home Technologies продолжает развиваться. Сейчас платформа для управления устройствами умного дома успешно разработана, все детали отшлифованы. Пришло время выходить на рынок и предлагать свои устройства пользователям. Без вашей помощи тут не обойтись!
Что и как предстоит сделать
Решено разработать интернет-магазин, в котором будут продаваться устройства Smart Home Technologies. У компании серьёзные планы, и магазин должен быть легко масштабируемым. Вот почему для разработки приложения выбрали микросервисный подход.
Как и всегда при разработке микросервисов, команде интернет-магазина придётся столкнуться с типичными инфраструктурными сложностями. Чтобы минимизировать риски, проект решили разрабатывать, опираясь на проверенные паттерны микросервисной архитектуры. А для их реализации будет использован проект Spring Cloud и его подпроекты.
Какие микросервисы будут в проекте
В начале разработки любого микросервисного приложения важно правильно разбить его на микросервисы. В противном случае это может привести к проблемам в будущем.

По этой схеме команда сформировала список основных бизнес-сущностей, которыми должен оперировать интернет-магазин. Таких сущностей получилось шесть: товары; корзины пользователей; заказы пользователей; оплата заказов; склад, на котором хранятся товары; доставка заказанных товаров.
Используя паттерн Decompose by Business Capability, команда выделила шесть ключевых микросервисов:
shopping-store — представляет собой витрину товаров, из которых пользователи выбирают товары для заказа.
shopping-cart — отвечает за работу с корзиной пользователей. Пользователи будут добавлять товары в корзину, чтобы сделать заказ.
order — работает с заказами пользователей, оформляет их.
warehouse — отвечает за склад.
payment — в этом сервисе сосредоточена логика, связанная с оплатой заказов.
delivery — ответственен за доставку готовых заказов пользователям.
Как микросервисы будут взаимодействовать друг с другом
Сервисы будут взаимодействовать между собой с помощью REST-вызовов.
Чтобы добиться максимальной изоляции сервисов друг от друга, каждый из них будет работать со своим набором данных. Другими словами, приложение будет следовать паттерну Database per Service.
Паттерн будет реализован на уровне схем БД: сервер базы данных для всего приложения останется общим, но каждый микросервис будет работать со своей схемой.

Что дальше
В ближайших двух спринтах вам предстоит помочь Smart Home Technologies в реализации проекта интернет-магазина.
В текущем спринте вы реализуете модули витрины товаров, корзины пользователей и склада. В следующем — сервис для оформления заказа, его оплаты и доставки.
В процессе вы потренируетесь применять изученные технологии — Spring Cloud Config, Eureka, Feign и Circuit Breaker. Это позволит ещё глубже погрузиться в мир разработки микросервисных приложений.
